# Google Play Data Safety — draft answers

Not submitted anywhere — there's no Google Play Console account yet (TODO.md Phase 17). This is a
reference draft so the Play Console form can be filled in quickly and *accurately* once the
account exists, generated by reading what the app's code actually does today, not guessed from
what a typical app usually declares. **Re-check this against the code before submitting** — if a
feature listed as "not built" here has shipped by then, its answer changes.

Mirrors the hosted Privacy Policy (`app/(app)/profile.tsx`'s Legal section) — the two must stay
consistent; if one changes, check the other.

## Does your app collect or share any of the required user data types?

**Yes.**

## Data types

| Data type | Collected? | Shared? | Processed ephemerally only? | Required or optional? | Purpose |
|---|---|---|---|---|---|
| Email address | Yes | No | No | Required | Account management |
| Name | Yes (display name) | No | No | Optional | App functionality |
| Photos | Yes (camera/gallery — proof submissions, screenshot-intelligence input) | Yes — sent to Anthropic (Claude API) for AI analysis | Yes for Screenshot Intelligence (never stored after analysis, no bucket exists for it); No for proof photos (retained in private storage while the mission/account exists) | Optional (both proof submission and screenshot scanning are user-initiated actions, not required to use the app) | App functionality |

**Not collected**: precise or approximate location, financial info, health/fitness data, messages,
audio recordings *(voice proof exists as a disabled "SOON" option — not shipped, don't declare it
until it is)*, files/docs beyond the same picker used for photos, calendar, contacts, web browsing
history, device/advertising IDs, crash logs or analytics *(no crash-reporting or analytics SDK is
integrated yet — Phase 15's known gap; add this row the moment Sentry/analytics ships)*.

## Data sharing detail — Anthropic (Claude API)

The one third party in this app. Photos submitted as mission proof, and screenshots submitted to
Screenshot Intelligence, are sent to Anthropic's API for AI judgment (proof plausibility; extracted
intentions). This is a service-provider relationship (data processor), not a sale or an advertising
share — mark it as "shared" on the form regardless, since Play's definition covers any transmission
to a third party, not just monetized sharing. Anthropic does not use API-submitted content to train
its models (per Anthropic's own API terms, not this app's control) and nothing is persisted by
Anthropic beyond serving the request.

## Security practices

- **Data encrypted in transit**: Yes — Supabase (HTTPS/TLS) and Anthropic's API (HTTPS/TLS) for
  every request.
- **Users can request data deletion**: Yes, in-app — Profile → Delete Account
  (`supabase/functions/delete-account`) permanently removes the account and every row that
  references it (missions, proofs, verifications, XP history, achievements), plus all proof media
  in Storage. This is real, tested, and doesn't require emailing support.
- **Independent security review**: A `/security-review` pass was run against this codebase
  (2026-09-05) — see TODO.md Phase 15 for what it covered and the one vulnerability it found and
  fixed. This isn't a third-party audit; don't represent it as one on the Play form.

## Committed to accuracy, not completeness-for-its-own-sake

Rows are absent here, not marked "no" with padding, when a feature simply doesn't exist yet
(voice proof, notifications, analytics, Focus Enforcement, any Google/Apple sign-in beyond email).
Declaring a permission or data type "not collected" for a feature that later ships without updating
this file — and the actual Play Console form — is exactly the kind of mismatch Google's own
guidance calls out as a policy violation. Re-derive this file from the code at submission time,
don't just copy it forward.
